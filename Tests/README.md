# 悬停跟踪回归验证

## 行为与修复

悬浮窗口展开后切换到其他普通应用，窗口应真正收回，之后仍能悬停展开。窗口只是被遮挡时，旧逻辑仍可能导出 `expanded_visible`；此时“鼠标在窗内”的几何缓存或快捷键等待会阻止收回，而再次悬停又被“已经展开”的检查拒绝。

- 收回检查将其他普通应用取得前台视作离开交互，绕过旧窗内缓存、快捷键等待和后台兄弟窗口几何，沿用原有宽限期收回（设置托管窗口保留动画，快捷键窗口瞬移），并保留新选中的应用焦点。
- frame 与边缘几何准备成功后才停止跟踪；准备失败仍返回 `false`，由原计时器继续检查，避免短暂 AX 读取失败后永久失去驱动。

现有 100ms 跟踪、220ms 宽限期，以及置顶、融合锁、动画中和鼠标按下等门禁不变。

## 运行

需要 macOS、Python 3 和 Swift Command Line Tools。


## 覆盖与边界

脚本原样提取生产 `checkMouseForCollapse`、`collapseWindow`、`expandWindow`、`startMouseTrackingTimer`、`revealForTemporaryStashTab` 和 `SnapState`，在内存平台后端中编译运行；不复制收回控制流，也不在生产代码添加测试分支。

- 左右两侧分别覆盖普通鼠标移出、Dock/快捷键展开后的窗外点击；准备读取失败后保留跟踪，读取恢复后收回，再次悬停可以展开。
- 覆盖几何准备失败、持续读取失败、鼠标返回后取消收回和随后再次移出；失败期间不启动动画或释放焦点。
- 前台切换覆盖旧窗内缓存、快捷键等待、后台兄弟窗口几何、动画中发生切换、失败读取恢复及鼠标按下；收回后不另行归还焦点。
- 同一应用保持前台、置顶、辅助应用取得前台及宽限期内切回，不触发额外收回。
- 计时器、时间、延迟队列、AX/UI 使用内存后端；动画仅模拟正常完成，不连接真实应用、显示服务或辅助功能设置。

真实 AX 超时、CoreVideo、跨显示器行为及长时间稳定性不由本套测试验证。

## 手动验收

1. 用临时收纳快捷键收纳一个普通窗口，再悬停展开。
2. 点击另一个普通应用，使其取得前台；确认源窗口真正收回，而非仅被覆盖。
3. 再次移到侧边条，确认无需额外点击即可展开。

本地构建以滴答清单和 ChatGPT 窗口完成连续两轮操作，反馈正常；同时观察到 `expanded_visible → snapped_hidden → expanded_visible` 状态切换。这是该操作场景的验证结果，不代表所有应用及长期使用场景均已验证。

### 设计与默认值

快捷键窗口不进入原融合条、软件级 owner 转移和软件快捷键 claim；设置里启用的软件仍走原路径，临时快捷键对它们不做新行为。快捷键读取方式、设置格式不变。每个快捷键会话独立保存收纳前 frame、最后展开位置和收纳序号；同软件排除使用仍在收纳的成员计数，最后一个退出后才解除。全部会话离开后，该软件下一轮序号从 1 开始。

`TemporaryStashDefaults` 集中定义：标签 **24 × 120 pt**、字体 **12 pt**、字行距 **15 pt**、文字内边距 **8 pt**、相邻间隙 **4 pt**。悬停读取 `AppConfig.shared.hoverDelayMS`（默认 **200 ms**，0 表示立即展开），tracking area 配合单次计时器响应；现有 **120 ms** 轮询校准状态。文字逐字从上到下绘制，过长末尾省略号；不显示图标、标题、分组。按显示器 ID 和边维护运行期有序列表（屏幕几何变化不清空顺序），从上到下紧邻排列，整列在 `NSScreen.visibleFrame` 居中，不依赖窗口中心；不处理排不下的情况。新窗口追加到底部，退出后保持其余顺序并重新居中。

同边切换同步收起旧窗口再展开新窗口；固定窗口跳过收回。标签面板保持 non-activating、不能成为 key/main window，仅标签矩形接收鼠标。拖动只改 y、限制在列范围内，其余标签暂不移动，松手后插入重排；按住标签期间锁住全部快捷键窗口的自动收回并暂停展开，单击没有额外动作。快捷键窗口收纳、展开和收回均瞬移，不走位置插值；收回先设 alpha 为 0 再移动，展开/取消先移动再恢复 alpha。收起窗口 alpha 为 0；设置托管窗口仍为原来的 0.01。取消/退出先停止位置动画和焦点回调：拖离取消保留松手 frame，不写回位置；快捷键取消和退出恢复原位置，原位置不在任何屏幕上时用最后展开位置。随后恢复 alpha 并销毁资源。对恢复位置时的 `cannotComplete` 重试一次；仍失败保留既有救援记录。动画完成/延迟折叠以及解除固定回调都使用世代校验，防止恢复后再次写入旧位置。离屏判定对快捷键窗口优先用 CGWindowID，无法取 ID 时回退原几何比对；连续负判定满 0.3 秒才隐藏，回屏立即显示。隐藏只 orderOut，离开管理才关闭面板；Space 切换不清空顺序或销毁面板。

快捷键收纳现在以新键 `SideBarTemporaryShortcutRecoveryV1` 持久化窗口身份、原位置、显示器/边、序号和标签顺序；包含系统启动会话 UUID，电脑重启后不复用旧身份。正常退出先保存意图，再恢复位置和可见性，不因会话销毁回调删除记录。启动时沿用 AppDelegate 的同步崩溃找回，再由就绪的 manager 严格按 pid + bundle ID + CGWindowID 重新收纳；不以标题或几何猜窗口。AX 暂时读不到时每 0.5 秒进行一轮最多 20 次的重试，之后由 5 秒同步周期、Space 变化及唤醒/解锁继续重试；只有 WindowServer 全窗口列表确认 CGWindowID 消失、且两秒后软件仍在运行时才删除关闭记录，软件退出则等待重启；恢复重试不再调用找回逻辑。恢复不激活软件、不安排焦点释放，图钉状态不恢复，鼠标停在恢复标签上时需先移开再移回。恢复序号在重试前预留，新窗口从最大预留序号之后分配；晚到窗口及屏幕/边回退保留原列相对顺序。

应用激活由 manager 统一路由到标签协调器，只选择当前 focused 收起会话；没有 focused 时才用 main，不会因 main 属于收纳窗口而覆盖一个普通 focused 窗口。复用悬停的同边先收后展逻辑，并检查定向激活和程序性激活门禁，避免自身 reveal 重入。AX 忙导致旧窗口无法收回时，下轮重试前重新核实焦点。⌘Tab/Dock 激活展开复用现有 Dock 交互等待，鼠标初始在窗外时不会立即收回；悬停展开仍按鼠标移出收回。其他标签保持显示与悬停响应。
